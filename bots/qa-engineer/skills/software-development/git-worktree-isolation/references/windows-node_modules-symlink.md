# Windows node_modules symlink for git worktrees

## Problem
A fresh `git worktree add` has no `node_modules` (gitignored). Running `npx tsx --test ...`
fails with `Cannot find module 'axios'` / `ERR_MODULE_NOT_FOUND` even though the sibling main
checkout has everything installed.

## Fix (Windows, MSYS / git-bash)
Create a directory symlink pointing at the main checkout's `node_modules`. Use `cmd /c` with a
PLAIN Windows path as the target (do NOT pass an MSYS `/c/...` path to `mklink`).

```bash
cd /c/one/avs-improvements
cmd /c "mklink /D node_modules C:\one\Automated-Video-Generator\node_modules"
```

## Pitfall: malformed target path
- WRONG (double prefix):  `cmd //c "mklink /D node_modules /c/C:/one/.../node_modules"`
  → link resolves to `/c/C:/one/...` which is invalid; tsx reports `Cannot find module 'axios'`
    for packages that exist. Fails SILENTLY at test time, not at symlink creation time.
- WRONG: `cmd //c` (double slash) — also produces a broken link on some shells.
- RIGHT: single `cmd /c`, target is `C:\one\...` (single backslash form, no `/c/` prefix).
  Result line reads: `symbolic link created for node_modules <<===>> C:\one\...\node_modules`

## Verify
```bash
node -e "console.log(require.resolve('axios'))"
# must print: C:\one\Automated-Video-Generator\node_modules\axios\dist\node\axios.cjs
```
If it errors, the symlink target is wrong — delete and recreate with the correct plain path.

## Cleanup / safety
- The symlink is untracked (gitignored) → it will NOT be committed or pushed. Safe to leave.
- To remove: `rm -f node_modules` (MSYS) before deleting the worktree.
- Linux/macOS equivalent: `ln -s /abs/main/node_modules /abs/worktree/node_modules`
